# 備品管理 Web アプリケーション

スマートフォンでの操作を前提にした備品管理アプリです。
QR コードを読み取って在庫ステータスをワンタップで更新することを主な用途としています。

サーバーは用意しません。GitHub Pages（静的配信）、Google Apps Script（API）、Google スプレッドシート（DB）だけで動きます。

---

## できること

- Google アカウントでログイン。**指定した Google グループのメンバーだけ**が利用可能
- 備品一覧（キーワード検索 / カテゴリ・場所・在庫ステータスでの絞り込み）
- QR コードをスキャンして該当備品を即座に表示
- 在庫ステータス（余裕あり / 残りわずか / 在庫なし）をワンタップで更新
- 備品の新規登録・編集・論理削除
- 撮影とアルバム選択から写真を追加（1備品4枚まで）。自動縮小してDriveに保存し、代表を一覧、全写真を詳細と拡大で表示
- 全操作を `logs` シートに記録（誰が・いつ・何を・どう変えたか）
- 貼り付け用 QR ラベルの生成と印刷（`docs/qr.html`）
- 2 回目以降の起動や詳細画面は、前回のデータをすぐに表示してから裏で最新に差し替える（後述「表示の高速化」）

## API 仕様

すべて `POST` の 1 エンドポイントで、ボディの `action` で処理を分岐します。

### リクエスト

```json
{
  "action": "getItems",
  "idToken": "＜Google ログインで取得した ID トークン(JWT)＞",
  "payload": { "keyword": "ケーブル" }
}
```

`Content-Type` は `text/plain;charset=utf-8` を使います。
`application/json` にするとブラウザが CORS プリフライト（OPTIONS）を送りますが、GAS はこれに応答しないためリクエストが失敗します。

### レスポンス

```json
{ "ok": true,  "data": { "items": [ ... ], "total": 12 } }
{ "ok": false, "error": { "code": "ITEM_NOT_FOUND", "message": "...", "status": 404 } }
```

GAS は常に HTTP 200 を返すため、成否は `ok`、種別は `error.status` で判断します。
シートへの書き込みを始めた後で失敗したときは `error.maybeSaved: true` が付きます（一部だけ保存された可能性がある）。

### アクション一覧

| action | payload | 返すもの |
|---|---|---|
| `loginCheck` | `withItems?`, `filters?` | ユーザー情報、カテゴリ・場所の候補、在庫ステータスの選択肢。`withItems` なら `filters`（`getItems` と同じ絞り込み）をかけた `items[]`, `total` も返す |
| `getItems` | `keyword?`, `category?`, `location?`, `stock_status?`, `restock?`（`true` なら残りわずか・在庫なしだけ） | `items[]`, `total` |
| `getItem` | `item_id`, `withLogs?` | `item`, `logs[]` |
| `createItem` | `name`, `category?`, `location?`, `stock_status?`, `quantity?`, `note?`, `item_id?`, `photos?`, `primary_photo_id?`, `photo?` | `item`, `log`。写真の一部失敗なら `photoErrors` と互換 `photoError` も |
| `updateStatus` | `item_id`, `stock_status`, `quantity?`, `note?` | `item`, `log` |
| `updateItem` | `item_id` と更新したい項目 | `item`, `log` |
| `deleteItem` | `item_id` | `item`（`is_deleted: true`）, `log` |
| `getLogs` | `item_id?`, `limit?` | `logs[]` |

`photo` は `{ "data": "＜base64＞", "mimeType": "image/jpeg", "filename": "..." }` の形式です。
更新系が返す `log` は、その操作で `logs` シートに追記した 1 行（`getItem` の `logs[]` と同じ形）です。

更新系（`createItem`／`updateStatus`／`updateItem`／`deleteItem`）の payload には、`op_id`（操作ごとに一意な ID）と `op_attempt`（何回目の送信か）を付けられます。
同じ `op_id` の送信は 1 回しか実行しません。すでに済んでいれば、現在の `item` と元操作の `log`・写真失敗情報に `replayed: true` を付けて返します。
途中で止まっていた場合（備品の行は書いたが履歴を追記する前に失敗した）は、続きを行ってから返します。
画面は、保存できたか分からない失敗のとき（通信の失敗、または `error.maybeSaved: true`）に、同じ `op_id` で送り直します。
応答待ちは読取60秒・保存7分で打ち切ります（`docs/config.js`）。保存の期限切れも結果未確定として同じ操作IDで確認し、下書きを保持します。ブラウザからの中断はGAS側の保存取消を保証しません。
`op_id` の無い送信も受け付けます（送り直しの判定をしないだけ）。

備品には、内容から作る版 `version` が付きます。`updateStatus`／`updateItem`／`deleteItem` の payload に、画面が読んだときの版を `base_version` として付けると、今の版と違う（他の人が先に更新した、またはシートが直接編集された）ときは何も保存せずに `CONFLICT` を返します。
`updateItem` は、変えた項目だけを送ります。写真を変えるときは `photos` 配列全体を送ります。

リクエストに `"debugTiming": true` を付けると、応答に GAS 内の処理時間の内訳（`timing`）が付きます（計測用。`PERF.md` 参照）。

### 複数写真の追加・取り外し・代表指定

応答の `item.photos` は追加順の `{id,url}` 配列、`item.photo_url` は代表のURLです。既存行の `photos` が空欄なら旧URLを1枚の代表として返します。移行時に既存行を書き換えません。

`photos` を指定すると写真集合を全置換します。残す写真は応答と同じ `{id,url}`、新しい写真は一意な文字列IDと `photo` を指定します。配列から省いた既存写真は取り外されます。`primary_photo_id` は配列内のIDです。代表を外して指定を省いた場合、残った先頭が代表になります。

```json
{
  "item_id": "ITEM-0001",
  "base_version": "＜読み取った版＞",
  "op_id": "＜新しい操作ID＞",
  "photos": [
    {"id": "A", "url": "＜保存済みAのURL＞"},
    {"id": "B", "photo": {"data": "＜base64＞", "mimeType": "image/jpeg", "filename": "B.jpg"}}
  ],
  "primary_photo_id": "B"
}
```

0〜4枚を指定できます。`photos: []` で全部を外します。`photos` を省く編集は写真を変えません。旧 `photo` と `photos` の併用は拒否します。旧 `photo` の編集は代表位置だけを置換し、ほかの写真を残します。

写真保存の一部が失敗しても通常項目と成功した写真は保存し、`photoErrors: [{id,message}]` を返します。希望の代表が失敗したら成功分の先頭を代表にします。上の例でA保存済み・B失敗なら、写真だけの再送もAの参照を含め、画像データはBだけ送ります。再送には新操作IDと部分成功応答の版を使います。応答が不明な間は元操作ID・payload・版を変えず確認します。同ID確認は現在の備品を返すので、他者が写真を変えていたら最新の全既存写真と失敗下書きを保持し、代表・取り外しをフォームで再確認します。上限超過分は待機させ、解決まで保存しません。

写真の変更は版と履歴の対象です。履歴には写真の前後と失敗IDを記録し、画像Base64は記録しません。行の確定後に参照を確認し、使われなくなったDriveファイルはゴミ箱へ移します。移動失敗は保存を失敗にせず実行ログに残します。確認不能時は写真を残します。履歴の古いURLは表示できなくなります。強制終了などで残るファイルの制約は [PHOTO.md](PHOTO.md) 項目6を参照してください。

### 主なエラーコード

| code | status | 意味 |
|---|---|---|
| `AUTH_REQUIRED` / `AUTH_INVALID_TOKEN` / `AUTH_TOKEN_EXPIRED` | 401 | 再ログインが必要 |
| `AUTH_AUD_MISMATCH` | 401 | クライアント ID の不一致 |
| `FORBIDDEN_NOT_MEMBER` | 403 | グループのメンバーではない |
| `ITEM_NOT_FOUND` | 404 | 備品が未登録 |
| `ITEM_ID_DUPLICATED` | 409 | 手入力した備品 ID の重複 |
| `CONFLICT` | 409 | 画面が読んだ後に備品が変わっていた（何も保存しない。`error.data.item` に最新の備品） |
| `OP_MISMATCH` | 409 | 同じ `op_id` の操作がすでに別の内容で保存されている（何も保存しない。`error.data.item` に保存済みの備品） |
| `VALIDATION_ERROR` | 400 | 入力値が不正 |
| `PHOTO_LIMIT` / `PHOTO_INVALID` / `PHOTO_TYPE_UNSUPPORTED` | 400 | 枚数超過、写真ID/参照/画像の不正、非対応形式 |
| `PHOTO_TOO_LARGE` | 413 | 写真1枚が6MiBを超える |
| `BUSY` | 503 | 他の更新と競合（再試行で解消） |
| `GROUP_LOOKUP_FAILED` / `CONFIG_MISSING` | 500 | 設定不備 |

## セキュリティ設計

- **入力は数式として扱わない。** 「=」「+」「-」「@」で始まる入力は、先頭に「'」を付けて文字のままシートに書きます（入力が数式として実行されないように）。
- **ID トークンは毎リクエスト検証する。** GAS 側は Google の tokeninfo エンドポイントに問い合わせ、`aud`（自分のクライアント ID か）、`iss`、`exp`、`email_verified` を確認します。フロントから送られてきたメールアドレスは信用しません。検証結果は最大 5 分（トークンの有効期限内）、グループ所属の判定結果は 10 分キャッシュします。
- **計測用の認証省略を本番へ再導入しない。** `PERF.md` 1.5は過去の計測記録です。`RELIABILITY.md` 6.3で専用ファイルを撤去済みで、通常のGoogle認証を通します。
- **認可はサーバー側だけで判断する。** 画面を隠すことはアクセス制御になりません。`doPost` はすべての `action` で `authenticate_()` を通ります。
- **秘匿値はコードに埋めない。** スプレッドシート ID・グループアドレス・Drive フォルダ ID はスクリプトプロパティに置きます。リポジトリが公開されても漏れません。
- **ID トークンをブラウザに永続化しない。** メモリ上にのみ保持し、再訪時は Google Identity Services の自動サインインで取り直します。
- **書き込みは `LockService` で直列化する。** 同時更新による行ズレと ID 採番の衝突を防ぎます。
- **端末に保存するのは備品データだけ。** 表示を速くするため、一覧と直近に開いた詳細（最大 50 件）を `localStorage`（キー `parts-cache:v1`）に保存します。ID トークンは保存しません。保存したデータは、ログアウトしたとき・グループ外と判定されたとき・別のユーザーでログインしたときに消します。共用の端末では、使い終わったらログアウトしてください。

なお、クライアント ID と GAS の URL は公開されても問題ありません。これらを知っていても、グループのメンバーでなければ API は 403 を返します。

## 運用上の目安

スプレッドシートを DB として使うため、規模が大きくなると読み込みが遅くなります。
一覧取得はシート全体を読むので、**備品 1,000 件程度までが快適に使える範囲**です。
読み取りは GAS の `CacheService` に置いた写しを使うので、シートを読むのは写しが無いときと更新の直後だけです。
それでも遅くなる場合は `getItems` にページングを入れる改修を検討してください。

**スプレッドシートを直接編集した内容は、変更トリガー（`installSheetTrigger`、[SETUP.md](SETUP.md) の STEP 5）を登録していればすぐアプリに出ます。** 登録していない場合や、別のスクリプト・Sheets API から書き換えた場合は最大 5 分かかります。アプリから行った更新はすぐに出ます。
すぐに反映させたいときは、GAS エディタで `onSheetChange` を実行してください。

`logs` は追記のみで増え続けます。**`logs` の行は、別シートへの退避も含めて、動かしたり消したりしないでください。** 送り直しの判定（`gas/Op.gs`）は、`logs` の `op_id` 列にある過去の操作の記録を毎回探します。行を動かすと、その操作の送り直しを新しい操作と取り違え、備品や履歴を二重に登録することがあります（`RELIABILITY.md` 1.6）。
スプレッドシートには容量の上限があり、`logs` の行が増えると送り直しの判定の検索も遅くなります。容量や処理時間が問題になってきたら、操作 ID の記録を保ったまま古い行を保管する別の方式を設計してから移してください。

## 表示の高速化

表示の待ち時間を減らすため、次のしくみを入れています。計測手順と改善前後の値は `PERF.md` にあります。

- **前回のデータをすぐ表示する。** 2 回目以降の起動、一覧から詳細、QR 読み取り後の詳細は、端末に保存した前回のデータをすぐに表示し、裏で最新を取得して差し替えます。そのため、ほかの人の更新が画面に出るまで数秒かかることがあります。
- **更新は押した直後に画面へ反映する。** 在庫ステータスの更新・編集・登録は、保存の完了を待たずに画面を変え、「保存中…」と表示します。保存に失敗したら元の表示に戻して知らせます（編集・登録は入力内容を残してフォームに戻ります）。
- **起動時の通信を 1 回にする。** ログインの確認と一覧の取得を 1 回の API で行います。
- **写真は表示の大きさに縮めて取る。** 一覧のサムネイルと詳細の写真は、Drive から表示サイズに合わせた画像を取ります。読み込みに失敗した写真は 1 回だけ読み直します。写真の要求には Referer を付けません（Google の写真サーバーが Referer によって 429 を返し、写真が表示されないことがあるため。PERF.md 6.1）。

## 保存の確実さと表示の新しさ

速い表示を保ったまま、保存の食い違いや古い情報の取り違えを防ぐしくみです。詳しい仕組みと検証は `RELIABILITY.md` にあります。

- **送り直しても二重に保存しない。** 保存のたびに操作 ID を付けます。通信が切れて保存できたか分からないときは、同じ操作 ID で自動で 2 回まで送り直します。サーバーは、同じ操作を 1 回しか実行しません。途中で止まっていた保存（備品は書いたが履歴を書く前に失敗したなど）は、送り直しのときに続きを行います。
- **保存できたか分からないときは、そう伝える。** 自動の送り直しでも分からなければ、「保存できたか確認できませんでした」と出し、入力を残してフォームに戻ります。もう一度押しても二重には保存されません。ステータス更新は、サーバーの状態を読み直して表示します。
- **写真だけ保存できなかったら、写真だけを送り直せる。** 登録・編集で写真の一部だけが保存できなかったときは、備品の変更は保存したうえで、詳細に「写真だけ送り直す」を出し、成功分は残して失敗画像だけ再送します。写真以外の項目は送らないので、その間の他の人の変更を上書きしません。
- **他の人の更新を上書きしない。** 画面が読んだ後に、他の人の更新やシートの直接編集で備品が変わっていたら、保存を止めて知らせます（何も保存しません）。編集は変えた項目だけを送ります。編集が止められたときは、入力を残してフォームに戻り、他の人が変えた項目を示します。自分が変えていない項目は最新の値にします。
- **いつの情報かを示す。** 一覧と詳細の上に「最新を確認中」「最新の情報です（何時に確認）」「通信できません（いつ確認した情報か）」を出し、「更新」「再試行」で取り直せます。1 日以上確かめていない情報は目立たせます。通信できないときに、空の一覧や「該当なし」と見せることはありません。
- **読み込めなかった写真を見分けられる。** 自動の読み直しでも読み込めなかった写真は「読めません」（一覧）、「写真を読み込めませんでした」（詳細）と出し、手で読み直せます。写真のない備品（📦）とは見た目が違います。
- **要補充をすぐ確かめられる。** 一覧の「要補充」ボタンで、残りわずか・在庫なしの備品だけを出せます。
