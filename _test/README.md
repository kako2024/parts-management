# テスト

デプロイ前にロジックを確認するためのものです。本番動作には不要なので、不要なら `_test/` ごと削除して構いません。

## `harness.js` — GAS の結合テスト

Apps Script の各サービス（`SpreadsheetApp` / `DriveApp` / `GroupsApp` など）をモックし、
`gas/` のコードを素の Node.js で走らせます。**依存パッケージなし**で動きます。

```bash
node _test/harness.js
```

認証・認可（トークン検証、`aud` 不一致、期限切れ、グループ外の拒否、計測用の認証省略）、
CRUD、採番、論理削除、履歴記録、処理時間の内訳（debugTiming）、読み取り用キャッシュ
（書き込み後の鮮度、読み取り途中の更新との競合、100KB を超える一覧の分割）の 38 項目を検証します。

`gas/` を編集したらこれを流してからデプロイすると、GAS エディタでの試行錯誤が減ります。

## `ui.js` — フロントエンドのスモークテスト

Playwright で実ブラウザ（iPhone 相当のビューポート）を起動し、
疑似 GAS API と疑似 Google ログインを相手に画面を操作します。
各画面のスクリーンショットが `_test/shot-*.png` に出力されます。

```bash
npm i playwright && npx playwright install chromium
node _test/ui.js
```

別のブラウザの実行ファイルを使うときは、環境変数 `CHROMIUM_PATH` で指定します。

ログイン → 一覧 → 検索 → 詳細 → ステータス更新 → 新規登録 → スキャン画面 → QRラベル生成 まで通します。
あわせて、表示の高速化（`PERF.md` 項目 3〜7）の動きを、疑似 API の応答を遅らせたり失敗させたりして確かめます。

- 起動時の API が 1 回であること、QR スキャナのライブラリをスキャン画面で初めて読み込むこと
- 前回のデータを API を待たずに表示し、最新に差し替えること、ログアウト・別ユーザーでキャッシュを消すこと
- 遅れて届いた古い応答で、画面とキャッシュが戻らないこと
- 更新を押した直後に画面へ反映し、失敗したら元に戻して知らせること
- 写真を表示の大きさに縮めて取ること、画面外の写真を読み込まないこと、失敗した写真を 1 回読み直すこと

## `perf-measure.js` — 所要時間の自動計測

ログイン済みの Chromium に CDP でつなぎ、本番の GAS を相手に場面 A〜D の所要時間を計ります。
手順と注意点（計測用の備品を登録して削除すること、ログインだけは人手で行うこと）は `PERF.md` の 1.5 節を参照してください。

```bash
node _test/perf-measure.js --out perf-result.json
```

結果の JSON は、`--check` で採用基準（`PERF.md` 1.3）を満たすか確かめ直せます（Playwright は不要）。

```bash
node _test/perf-measure.js --check perf-results/2026-09-26-final.json [--scenes C]
```

## `optimistic-failcheck.js` — 更新の失敗時の確認

本番の GAS を相手に、ステータス更新の通信を途中で失敗させ、表示が元に戻って失敗が通知されることを確かめます（`PERF.md` 4.4）。
使い方はファイル冒頭を参照してください。
