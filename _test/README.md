# テスト

デプロイ前にロジックを確認するためのものです。本番動作には不要なので、不要なら `_test/` ごと削除して構いません。

## `harness.js` — GAS の結合テスト

Apps Script の各サービス（`SpreadsheetApp` / `DriveApp` / `GroupsApp` など）をモックし、
`gas/` のコードを素の Node.js で走らせます。**依存パッケージなし**で動きます。

```bash
node _test/harness.js
```

認証・認可（トークン検証、`aud` 不一致、期限切れ、グループ外の拒否、計測用の認証省略）、
CRUD、採番、論理削除、履歴記録、処理時間の内訳（debugTiming）、読み取り用キャッシュ
（書き込み後の鮮度、読み取り途中の更新との競合、100KB を超える一覧の分割、変更トリガー）に加えて、
`RELIABILITY.md` の項目を検証します（全 84 項目）。

- 送り直しを二重に実行しないこと（応答の喪失、1 回目の送信が 2 度届く、途中で止まった保存の続き、別の利用者の送り直しの拒否、500 件を超える履歴）
- 写真・履歴の保存の途中失敗（`maybeSaved`、写真だけの送り直し）、数式と「=」で始まる文字を保つこと
- 同時編集の競合（古い版の保存を止める、書く直前の直接編集・行のずれ）、要補充の絞り込み
- 0/1/4枚・代表・旧URL移行・既存参照検証・部分失敗/履歴回復とDriveファイルの安全な片付け

シートのモックは、本物と同じく「=」で始まる文字を数式に、「'」で始まる文字を文字のままに、数字だけの文字を数値に変えます。

`gas/` を編集したらこれを流してからデプロイすると、GAS エディタでの試行錯誤が減ります。

## `ui.js` — フロントエンドのスモークテスト

Playwright で実ブラウザ（iPhone 相当のビューポート）を起動し、
疑似 GAS API と疑似 Google ログインを相手に画面を操作します。
各画面のスクリーンショットが `_test/shot-*.png` に出力されます。

```bash
npm i playwright && npx playwright install chromium
node _test/ui.js
```

別のブラウザの実行ファイルを使うときは、環境変数 `CHROMIUM_PATH` で指定します。

ログイン → 一覧 → 検索 → 詳細 → ステータス更新 → 新規登録 → スキャン画面 → QRラベル生成 まで通します。
あわせて、表示の高速化（`PERF.md` 項目 3〜7）の動きを、疑似 API の応答を遅らせたり失敗させたりして確かめます。

- 起動時の API が 1 回であること、QR スキャナのライブラリをスキャン画面で初めて読み込むこと
- 前回のデータを API を待たずに表示し、最新に差し替えること、ログアウト・別ユーザーでキャッシュを消すこと
- 遅れて届いた古い応答で、画面とキャッシュが戻らないこと
- 更新を押した直後に画面へ反映し、失敗したら元に戻して知らせること
- 写真を表示の大きさに縮めて取ること、画面外の写真を読み込まないこと、失敗した写真を 1 回読み直すこと

保存の確実さと表示の新しさ（`RELIABILITY.md`）の動きも確かめます。疑似 API は、操作 ID による送り直しの判定・版による競合・応答だけを失わせる（`apiLose`）・写真だけの失敗（`photoFail`）・403 を真似ます。

- 応答が失われても同じ操作 ID で送り直し、二重に登録しないこと。確認できないときはフォームに戻ること
- 写真だけ保存できなかったら「写真だけ送り直す」で写真だけを送ること
- 編集は変えた項目だけを送り、競合したら入力を残してフォームに戻ること
- 状態の行（確認中・最新・通信できない・古い情報）、絞り込み後の失敗を「該当なし」と見せないこと
- 読み込めなかった写真の表示と手での読み直し、画面を離れた後に取りに行かないこと、要補充の絞り込み

複数写真の撮影/アルバム、圧縮・EXIF、4枚上限・代表・取消、全詳細・拡大のフォーカス、部分失敗と応答喪失後の他者写真保持、競合時の待機下書きも確認します。OSの選択画面・実HEIC・実機・実スクリーンリーダーは未確認です。

外部CDNが不安定な環境では、同じCDN応答を一時保存して `TAILWIND_SCRIPT`（既定 `/tmp/parts-tailwindcdn.js`）や既存の `/tmp/qrcode.min.js` の差し替えを使えます。製品の配信は変更しません。`--only ＜ラベルの部分文字列＞` はログインと指定項目だけを実行します。依存する確認は全実行してください。

## `perf-measure.js` — 所要時間の自動計測

ログイン済みの Chromium に CDP でつなぎ、本番の GAS を相手に場面 A〜D の所要時間を計ります。
手順と注意点（計測用の備品を登録して削除すること、ログインだけは人手で行うこと）は `PERF.md` の 1.5 節を参照してください。

```bash
node _test/perf-measure.js --out perf-result.json
```

結果の JSON は、`--check` で採用基準（`PERF.md` 1.3）を満たすか確かめ直せます（Playwright は不要）。

```bash
node _test/perf-measure.js --check perf-results/2026-09-26-final.json [--scenes C]
```

## `optimistic-failcheck.js` — 更新の失敗時の確認

本番の GAS を相手に、ステータス更新の通信を途中で失敗させ、表示が元に戻って失敗が通知されることを確かめます（`PERF.md` 4.4）。
使い方はファイル冒頭を参照してください。

## 写真の回帰と場面Dのローカル比較

```bash
node _test/photo-compress-regression.js
node _test/photo-perf.js
```

圧縮回帰は固定した変更前コミットと現在のcompressImageを隔離VMで比較します。場面Dは変更前1枚/現在1枚/現在4枚の20備品を生成写真と読み取り専用ローカルAPIで各5回比較します。Fast 4G・キャッシュ無効・430×932で `docs/perf.js` の記録を採取し、中央値と各回を `photo-perf-result.json` に保存します。一時HTTPS証明書用のopenssl、PlaywrightとChromium、同一Tailwind CDN応答の一時ファイルが必要です。比較対象のコミットを含むgit履歴も必要です。実GAS/Google画像配信・OS操作の確認にはなりません。

複数スクリプトは並列実行し、失敗したものだけ単独で再確認します。本計画では `perf-measure.js` と `optimistic-failcheck.js` の本番接続は行いません。前者の保存済みJSONの `--check` と全スクリプトの構文確認はオフラインで実行できます。

## `api-regression.js` — QRと通信期限の回帰

`node _test/api-regression.js` で実際のフロント関数を隔離し、正常/不正QR、応答/本文の保留、本文の読取失敗、期限後の同ID/同じ版/写真下書きによる確認、タイマーの片付けを確かめます（6件）。期限後の二重登録防止と入力名は `ui.js` のモバイル模擬でも確認します。採番の9999/999境界は `harness.js` に含みます。
